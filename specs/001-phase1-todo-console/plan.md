# Implementation Plan: Phase I Todo Console Application

**Branch**: `001-phase1-todo-console` | **Date**: 2025-12-27 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-phase1-todo-console/spec.md`

## Summary

Phase I implements an in-memory Python console application for basic task management. The application provides CRUD operations (Create, Read, Update, Delete) plus completion status toggling through a menu-driven CLI. All data exists only during runtime with no persistence. Implementation uses Python standard library only, with clean separation between model, service, and CLI layers.

## Technical Context

**Language/Version**: Python 3.11+
**Primary Dependencies**: None (Python standard library only)
**Storage**: In-memory dictionary (no database, no files)
**Testing**: pytest (for unit tests)
**Target Platform**: Any system with Python 3.11+ (Windows, macOS, Linux)
**Project Type**: Single project (console application)
**Performance Goals**: Instant response for all operations (<100ms)
**Constraints**: No external dependencies, no persistence, single-user
**Scale/Scope**: Single user, unlimited tasks (memory-limited)

## Component Specifications

### 1. Task Model (`src/models/task.py`)

**Purpose**: Define the Task entity as a Python dataclass.

**Implementation**:
- Use `@dataclass` decorator
- Fields: id, title, description, is_complete, created_at
- Type hints for all fields
- Default values: description="", is_complete=False

**Dependencies**: `dataclasses`, `datetime` (standard library)

### 2. TaskManager Service (`src/services/task_manager.py`)

**Purpose**: Encapsulate all business logic for task operations.

**Implementation**:
- Class with `_tasks: Dict[int, Task]` storage
- Class/instance attribute `_next_id: int` for ID generation
- Methods per contracts/task-service.md:
  - `add_task(title, description="")`
  - `get_all_tasks()`
  - `get_task(task_id)`
  - `update_task(task_id, title=None, description=None)`
  - `delete_task(task_id)`
  - `mark_complete(task_id)`
  - `mark_incomplete(task_id)`

**Validation**:
- Raise `ValueError` for empty/whitespace titles
- Return `None` for task-not-found scenarios

### 3. CLI Menu (`src/cli/menu.py`)

**Purpose**: Handle all user interaction (display and input).

**Implementation**:
- `display_menu()` - Show main menu options
- `get_user_choice()` - Capture and validate menu selection
- `get_task_id_input()` - Capture and validate task ID input
- `add_task_flow(manager)` - Handle add task interaction
- `view_tasks_flow(manager)` - Handle view tasks display
- `update_task_flow(manager)` - Handle update task interaction
- `delete_task_flow(manager)` - Handle delete task interaction
- `mark_complete_flow(manager)` - Handle mark complete interaction
- `mark_incomplete_flow(manager)` - Handle mark incomplete interaction

**Error Handling**:
- Catch `ValueError` from non-numeric ID input
- Catch `ValueError` from service for invalid titles
- Display user-friendly error messages per spec

### 4. Main Entry Point (`src/main.py`)

**Purpose**: Application entry point and main loop.

**Implementation**:
```python
def main():
    manager = TaskManager()
    while True:
        display_menu()
        choice = get_user_choice()
        if choice == 7:
            print("Goodbye!")
            break
        # Route to appropriate flow based on choice
```

## ID Generation Strategy

**Algorithm**: Simple incrementing counter

```python
class TaskManager:
    def __init__(self):
        self._tasks: Dict[int, Task] = {}
        self._next_id: int = 1

    def add_task(self, title: str, description: str = "") -> Task:
        task_id = self._next_id
        self._next_id += 1
        # Create and store task...
```

**Guarantees**:
- IDs start at 1 (user-friendly)
- IDs never reused (even after delete)
- IDs always increment

## Error Handling Strategy

| Error Scenario | Detection Point | Response |
|----------------|-----------------|----------|
| Empty title | Service layer | Raise `ValueError` |
| Whitespace-only title | Service layer | Raise `ValueError` |
| Task not found | Service layer | Return `None` |
| Invalid ID format | CLI layer | Catch `ValueError` from `int()` |
| Invalid menu choice | CLI layer | Validate against 1-7 range |

**Error Message Standards** (from spec):
- `Error: Task with ID X not found.`
- `Error: Task title cannot be empty.`
- `Invalid choice. Please enter a number between 1 and 7.`
- `Error: Please enter a valid numeric ID.`
